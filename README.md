# 老家 · 院落里的时光

在网页里旋转、缩放、平移查看老家院落，支持电脑和手机。所有运行所需的模型、贴图和查看器代码均随站点托管，无需个人服务器。

**打开模型：<https://zhouguangyuan0718.github.io/hometown-3d/>**

![分享二维码](public/qr.png)

## 操作

- 电脑：左键拖动旋转，滚轮缩放，右键拖动平移；聚焦三维视图后可用方向键平移。
- 手机：单指旋转，双指缩放和平移。
- 工具栏：全景复位、俯视、自动旋转、全屏。
- 右上角分享按钮：显示二维码、复制链接。

### 步行漫游

点击「步行」切换到院门外的人眼视角，可以从敞开的院门进入下院，再沿石阶走到上院。

- 电脑：WASD 或方向键前后左右走动，按住鼠标拖动画面转头；Q / E 也可左右转向，Shift 加快行走。
- 手机：按住左下角方向键移动，另一只手指拖动画面转头，支持同时操作。
- 「回到门口」重置位置和朝向；「全景」或 Esc 退出步行。

步行区域由原始 v42 场景的可见几何离线生成，使用 0.12 场景单位网格以及台阶高度限制。视线以用户提供的下院瓦房门高 1.8 米为比例基准：门板在模型中约高 3.07 单位，因此 1 米约为 1.706 场景单位，1.62 米视线对应约 2.763 单位。该标定用于步行视角，不代表整个照片复原模型均为实测尺寸。

只开放与院门连通的地面，并对墙体、头顶空间和地台边缘做通行检查。v42 院门抬高后可按正常眼高连续通过；其他局部低处仍会按网格净空自动降低视线。房屋内部没有完整建模，未开放通行。导航数据与查看器在点击步行时才加载，不改变 GLB 或其缓存版本。

`pnpm test` 验证门口起点、上下院连通、台阶往返、墙体与边缘阻挡。需要重新生成导航数据时，使用 Blender 在后台只读打开原工程：

```sh
python3 scripts/calibrate-walk-scale.py /path/to/source.glb
blender -b /path/to/source.blend --python scripts/build-walk-map.py
pnpm test
```

## 模型来源

网页模型来自「老家_院门净高与旧木构修正_v42.glb」，依据老家照片复原。v42 参照院门照片，将门洞最低净高调整为约 2.10 米，保留原平面位置、基脚、梁和压顶厚度；2.10 米是按照片比例作出的推测，未实测院门。部分地面、老化与未拍摄区域的细节为推测还原，并非测绘成果。

本仓库只包含浏览用的优化模型；Blender 工程、原始照片和原始 GLB 保留在本地。优化包括网格合并、有限误差简化、Meshopt 压缩、最长边 2048 像素的 WebP 贴图。精度参数和文件校验值见 `model-info.json`。

## 本地开发

使用 Node.js 24 与 pnpm 11.19.0：

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm build
pnpm preview
```

重新生成浏览模型：

```sh
pnpm exec gltf-transform optimize /path/to/source.glb public/model.glb \
  --compress meshopt --texture-compress webp --texture-size 2048 \
  --simplify-error 0.0002 --simplify-ratio 0.5 \
  --simplify-lock-border true --instance false
```

推送 `main` 后，GitHub Actions 自动构建并发布 GitHub Pages。`revision.txt` 记录线上站点对应的源代码提交。

网页公开访问，浏览用 GLB 也可通过网址获取。模型未另行授予转载或商用许可；依赖库遵循各自的开源许可证。

## 再次打开时的缓存

成功下载后，网页通过 CacheStorage 将模型保存在当前浏览器。再次访问相同版本时直接读取本地模型，不发出模型下载请求。缓存键包含模型 SHA-256，读取和下载均检查文件完整性；更新模型后自动下载新版本并清理该模型的旧版本。构建时检查 `model-info.json` 与模型文件匹配。

页面会区分下载、读取已保存的模型、准备画面三个阶段。本地缓存只省去网络下载，每次打开仍需解析网格、解码贴图并准备显卡资源。清理网站数据、隐私模式、存储空间不足或浏览器自动回收可能使缓存不可用；此时正常从网络加载。网页本身仍需要联网打开。
